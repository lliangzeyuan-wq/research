```
### 3. 连续推理会把复杂声事件进一步简化

作者把连续音频切成 1 秒窗口，每个窗口只给一个“主导类别”。这带来两个后果：

- 两只猪在同一个窗口里叫，可能只算成一次检测。
- 一次持续较长的攻击性叫声，可能被相邻窗口重复计算。
- 模型置信度低于 0.7 的窗口统一归为“安静”，可能把真实但较弱的咳嗽也删掉。

论文抽查 2000 个窗口，约 **4.6% 存在重叠或类别歧义**。虽然删除这些窗口后总体方向没有改变，但绝对事件数量会变化。
```

## 问题本质

连续推理本身没有问题，问题是：**把连续声音强行切成固定的 1 秒片段，每个片段只保留一个“主导类别”，再用一个统一阈值决定保留还是删除。**

这相当于把三个不同任务混在一起：

```
有没有声音？
是什么声音？
有几只猪在叫？
```

固定窗口只输出一个类别，因此会出现三种错误：

- **多算少**：同一秒内两只猪咳嗽，被合并成一次；
- **少算多**：一次持续 3 秒的攻击性叫声，被相邻窗口算成多次；
- **真实事件被删掉**：置信度 0.65 的弱咳嗽被直接改成“安静”。

所以 4.6% 的重叠或歧义只是表面现象，核心问题是**事件边界、重叠关系和事件数量都被窗口分类抹掉了**。

## 解决方案

### 1. 从“窗口分类”改成“声音事件检测”

不要先固定 1 秒，再强行给一个类别，而要让模型输出：

```
第 2.3—2.7 秒：咳嗽样事件
第 2.5—4.8 秒：攻击性叫声
```

也就是同时预测：

- 事件开始时间；
- 事件结束时间；
- 类别；
- 置信度；
- 是否与其他事件重叠。

可以采用帧级或短时间窗模型，例如每 20—50 ms 输出一次结果，再做事件聚合。注意：这里说的 frame 是音频帧，不是视频帧。

### 2. 改成多标签分类，不要只给一个主导类别

一个窗口可以同时是：

```
咳嗽：有
普通叫声：有
风机噪声：有
```

而不是强行三选一。多标签输出可以避免：

- 一次咳嗽和一次普通叫声重叠时，只保留其中一个；
- 重叠声音被模型当成一种全新的声音类别。

训练时应允许一个样本有多个标签，并使用多标签损失函数，而不是单标签交叉熵。

### 3. 把“低置信度”改成“噪声或不确定”，不要直接算安静

目前逻辑是：

```
置信度 < 0.7 → 安静
```

更合理的是：

```
置信度高 → 对应声音类别
置信度中等 → 不确定，等待更多上下文
置信度低且无目标能量 → 噪声或安静
```

应该单独设置：

- `noise`：风机、饲料机、人员活动；
- `overlap`：多个声源重叠；
- `unknown`：模型不认识；
- `uncertain`：模型暂时不能判断。

这样弱咳嗽不会被自动删除，而是进入“需要复核”或“低置信度事件”。

### 4. 使用连续概率和后处理，不要直接按窗口计数

推荐流程：

```
连续音频
→ 帧级多标签概率
→ 时间平滑
→ 起止点检测
→ 重叠处理
→ 去重和合并
→ 事件级计数或时间占用率
```

具体后处理可以包括：

- **非极大值抑制**：相邻窗口重复识别同一个事件时只保留一个；
- **事件合并**：间隔很短的同类事件合并为一次；
- **持续时间过滤**：避免把极短噪声尖峰当成咳嗽；
- **双阈值或滞回阈值**：开始用高阈值，结束用低阈值，避免一个事件被切碎；
- **峰值计数**：根据连续概率曲线的峰值数量估计事件次数，而不是统计窗口个数。

### 5. 每个类别使用不同阈值

咳嗽、喷嚏、攻击性叫声的声学难度不同，不应该共用 0.7。

可以分别校准：

```
咳嗽阈值：优先保证召回率
喷嚏阈值：优先控制误报
攻击性叫声阈值：根据持续时间调整
```

如果研究目标是早期预警，可以允许一些误报，但不能轻易漏掉弱咳嗽。阈值应通过验证集和临床/人工事件标签来确定。

### 6. 如果必须精确计数，需要增加空间信息

固定窗口的主要问题是无法解决重叠声源。若研究要求：

- 精确知道有几只猪在咳；
- 判断是同一头猪还是不同猪；
- 区分多个并发事件；

仅靠单麦克风通常不够，需要：

- 多麦克风阵列；
- 声源定位；
- 声源分离；
- 音频与视频或栏位信息融合。

如果硬件无法增强，就应降低目标，不追求精确个体计数。

### 7. 评价指标也要改成事件级

不要只看窗口分类准确率或 macro-F1，还要看：

- 事件召回率和误报率；
- 每小时误报次数；
- 起止时间误差；
- 重叠事件检测能力；
- 事件计数误差；
- 低置信度事件的保留率；
- 时间占用率和预警提前量。

## 推荐的最简方案

先把任务定义为：

```
房间级咳嗽样事件强度 + 时间占用率 + 不确定度
```

流程改成：

```
多标签事件检测
→ 分类别阈值
→ 去重合并
→ 事件级计数
→ 小时级趋势
```

如果确实需要个体级计数，再增加：

```
多麦克风 + 声源定位 + 声源分离 + 多模态信息
```

一句话总结：

> ==**不要用固定 1 秒窗口和单一标签去处理连续、重叠、长短不一的声音。应该做事件检测、多标签识别、分类别阈值和事件级去重；精确计数则必须依赖多麦克风或个体信息。*==*
